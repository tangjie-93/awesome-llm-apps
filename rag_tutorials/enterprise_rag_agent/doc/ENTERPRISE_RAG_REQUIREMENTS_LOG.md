# Enterprise RAG 需求迭代记录

> 目标：记录每次需求变化、范围调整和待确认事项，保证文档和系统同步演进。

## 记录规范

- 新增或修改需求时，先更新主需求文档。
- 再补一条迭代记录，说明为什么改、改了什么、影响什么。
- 任何未确认事项都要显式保留，不要悄悄默认。

## 迭代历史

### v0.9

- 日期：2026-08-19
- 来源：阶段 3/4 图谱、多模态和受控诊断处置继续实现
- 内容：
  - 新增 SQLite 图谱实体提及和同块共现关系存储，文档增量导入、替换、删除和目录同步清理会同步维护图谱数据。
  - 新增图谱概览和多跳查询 API，支持 1 到 3 跳路径返回，并对图谱概览、查询和问答补召回执行当前租户和文档权限过滤。
  - 新增 PNG/JPEG 图片接入，使用文件名、图片尺寸与可选同名人工说明生成检索文本，复用现有向量、权限和租户隔离链路。
  - 新增受审批令牌控制的失败导入诊断回放，校验当前租户、失败状态和路径存在性，记录请求、回放和完成审计。
- 验收：
  - 后端 `python -m unittest discover -s tests` 通过，15 个测试全部成功，覆盖图谱多跳/隔离、图片检索和诊断审批回放。
  - 前端 `npm.cmd run build` 通过。
