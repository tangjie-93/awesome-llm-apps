# Enterprise RAG 阶段 0 边界清单

> 版本：v0.1
> 日期：2026-08-13

## 目的

把阶段 0 需要先确认的业务边界落成可执行清单，供后续实现和评审直接引用。

## 首批服务对象

建议首批只覆盖三类内部知识场景：

- `security`：安全制度、事件响应、访问控制
- `hr`：入职、培训、员工手册
- `it`：备份、运维、基础 IT 规范

## 首批知识库

建议知识库与部门一一对应：

- `security`
- `hr`
- `it`

其中 `general` 可作为默认兜底知识库，但不作为首批重点边界的主要承载。

## 首批数据源

建议只接入结构稳定、容易引用的文本类文档：

- Markdown
- 纯文本
- 结构化 FAQ

暂不纳入：

- 音频
- 视频
- 扫描版 PDF
- 图片为主的材料

## 权限粒度

当前阶段采用“文档/切块组权限”即可，最小粒度建议如下：

- `public`
- `security`
- `hr`
- `it`
- `ops`

规则：

- 文档默认 `public`
- 敏感文档必须显式打组
- 查询结果必须先过权限过滤，再进入最终回答
- 阶段 0 不做段落级、字段级、租户级复杂权限

## 风险分级

建议分三档：

- `low`：公开流程、通用说明
- `medium`：内部制度、操作规范
- `high`：安全、合规、员工敏感信息

约束：

- `high` 级内容默认不允许直接生成答案
- `high` 级内容只能用于检索提示和人工复核
- 若业务确认需要回答，必须补审批和审计

## 本期不做

- 多租户隔离
- 段落级权限
- 自动执行操作
- 多模态输入
- 知识图谱

## 配置约定

建议把以下内容放入配置或初始化数据，而不是写死在前端：

- 默认知识库列表
- 默认部门组
- 风险等级映射
- 敏感数据白名单/黑名单

## 已确认项

1. `ops` 作为正式组保留。
2. `high` 级内容允许模型直接生成答案，但必须人工复核和审批。
3. 默认知识库必须存在 `general`。
4. 首批文档允许继续扩充外部导入。

## 影响

- `ops` 可以作为正式权限组写入配置和权限文档。
- `high` 级内容在前端与后端都要保留风险标识。
- `general` 作为默认知识库必须始终存在。
- 外部导入不再是阶段 0 的待确认项，后续实现可以继续沿用。
