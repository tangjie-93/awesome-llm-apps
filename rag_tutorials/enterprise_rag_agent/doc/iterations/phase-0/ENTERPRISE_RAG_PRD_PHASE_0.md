# Enterprise RAG PRD - 阶段 0：需求和边界

> 版本：v0.1
> 日期：2026-08-13

## 目标

把项目边界说清楚，避免后续实现偏题。

## 现状判断

当前代码已经具备阶段 0 的一部分能力，但还不完整：

- 已有按组权限控制，支持 `allowed_groups` 和 `user_groups`。
- 已有导入、检索、问答和日志链路。
- 已有基础知识库概念和文档元数据。
- 但还没有把“首批业务部门、数据源、风险分级、权限粒度”写成明确的需求约束。
- 也没有把这些约束沉淀到前端配置或后端配置层中。

## 范围

- 服务部门和业务域
- 数据源类型和接入方式
- 敏感数据范围
- 权限模型
- 错误答案的业务风险
- 本期做什么、不做什么

## 需求

1. 明确首批服务对象。
2. 明确首批文档类型。
3. 明确权限粒度。
4. 明确风险分级。
5. 明确阶段划分和交付边界。
6. 明确哪些配置来自代码默认值，哪些必须由业务侧提供。
7. 明确哪些内容只能用于内部评估，不能直接作为对外回答依据。
8. 输出可直接进入实现的阶段 0 边界清单。

## 验收

- 有统一的业务范围说明。
- 有明确的风险边界和权限边界。
- 有可执行的迭代路线。
- 有一份可持续维护的首批数据源和知识库清单。
- 有一份可执行的权限规则说明。
- 有一份阶段 1 可直接继承的输入约束说明。
- 阶段 0 边界清单已单独成文并可被实现引用。

## 已确认口径

- `ops` 作为正式组保留。
- `high` 级内容允许模型出答案，但必须人工复核和审批。
- 默认知识库保留 `general`。
- 首批文档允许继续扩充外部导入。

## 建议补齐项

1. 在 `doc` 目录补一份首批业务范围清单。
2. 在配置层补一份知识库和数据源约束说明。
3. 在权限文档里补最小粒度规则。
4. 在前端增加只读的范围说明页或配置展示页。
5. 将边界清单作为阶段 1 的输入前置条件。
6. 将业务范围清单和权限规则说明纳入索引页。
7. 将配置约定和前端只读展示需求纳入索引页。
