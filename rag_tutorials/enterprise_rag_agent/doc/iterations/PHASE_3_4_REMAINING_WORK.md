# 阶段 3/4 未完成工作清单

> 更新日期：2026-08-19
>
> 目的：记录 Enterprise RAG 阶段 3 和阶段 4 中尚未完成、需要生产环境依赖或业务决策确认的工作。本文不将已完成的基础能力重复列为待办。

## 当前结论

- 阶段 3 已具备认证接入骨架、租户级数据隔离、权限校验、审计、用量统计、失败导入回放和管理能力；当前主要缺少生产身份源和组织审批流程的正式接入。
- 阶段 4 已具备多知识库路由、受控 Web fallback、运行诊断、人工反馈、SQLite 知识图谱、图片文本化检索和受控失败导入处置；当前主要缺少模型驱动的跨模态能力、图谱质量能力和反馈驱动的自动优化闭环。
- 下列事项中，涉及真实身份提供方、模型供应商、审批制度或线上治理策略的内容，不能仅靠本地代码默认实现，需要先完成对应的环境或产品决策。

## 阶段 3：企业能力补齐

### P0：生产身份提供方接入

**现状**

- 系统支持 JWT/OIDC Bearer Token 解析、用户组和租户声明映射，以及基于角色的 API 权限校验。
- 当前配置适用于本地测试、演示或已有上游网关已完成身份验证的场景。

**未完成内容**

- 对接实际 OIDC Provider 的 JWKS、公钥轮换和签名验证。
- 配置并强制校验 Issuer、Audience、过期时间和允许的签名算法。
- 根据实际 IdP 的 Claim 结构确定用户 ID、显示名、邮箱、用户组、角色和租户字段映射。
- 为开发、测试、预发布和生产环境配置独立的身份提供方参数和密钥管理策略。

**前置依赖**

- 已确定的 OIDC Provider，例如 Microsoft Entra ID、Keycloak、Okta 或企业统一认证平台。
- 租户 Claim、用户组 Claim、角色 Claim 的正式字段约定。
- 密钥和证书的托管方式，以及 JWKS 网络访问策略。

**验收标准**

- 使用生产身份提供方签发的有效 Token 可以访问授权接口。
- 无效签名、错误 Issuer、错误 Audience、过期 Token 和缺失租户 Claim 均被拒绝。
- 同一用户在不同租户下只能访问对应租户的数据、日志、图谱和用量。

### P0：组织级审批工作流

**现状**

- 审计删除、审计清理和失败导入诊断回放要求服务端配置的审批令牌。
- 每次处置请求及完成结果均写入审计日志。

**未完成内容**

- 审批申请、审批人、审批状态、审批意见、审批有效期和审批撤销。
- 按操作风险和组织层级配置单级或多级审批规则。
- 审批通过后一次性授权执行，并防止令牌被重复或跨租户使用。
- 审批失败、执行失败和人工撤销后的回滚或补偿流程。

**前置依赖**

- 审批制度、审批角色和风险分级规则。
- 可接入的工作流系统或审批平台，或明确由本系统承担审批状态存储和通知。

**验收标准**

- 高风险操作必须关联有效审批记录后才可执行。
- 审批记录具备完整审计信息，且审批权限与执行权限可分离。
- 审批过期、撤销、跨租户和重复执行请求均被拒绝。

### P1：生产级用户、角色和租户治理

**现状**

- 已支持用户、角色、权限、用户角色关联和租户级用户查询。
- 已覆盖文档、切块、回答日志、操作日志、审计日志、反馈和用量的租户隔离。

**未完成内容**

- 用户与组织/租户的权威来源、同步方向和失效策略。
- IdP 用户组与本地角色之间的自动映射、冲突处理和撤权时效。
- 角色是否应租户级创建，或是否允许跨租户复用全局角色。
- 用户禁用、离职、组织迁移和权限变更后的历史审计保留策略。

**验收标准**

- 用户生命周期变化可在约定时效内同步至系统权限。
- 角色、用户和租户的归属规则可通过接口和审计记录追溯。
- 不存在跨租户用户管理、角色授予或反馈/回答日志错误关联。

## 阶段 4：高级能力

### P1：知识图谱实体质量和关系语义

**现状**

- SQLite 中已保存实体提及与同一切块内的 `co_occurs` 共现关系。
- 支持图谱概览、1 至 3 跳查询和权限过滤后的图谱补召回。

**未完成内容**

- 使用领域词典、NER 模型或 LLM 提升实体抽取准确性。
- 实体消歧、别名管理和规范化，例如简称、全称、大小写差异和同名实体区分。
- 从文本中提取显式关系类型，而非仅使用共现关系。
- 图谱质量评测，包括实体准确率、关系准确率、覆盖率、重复率和图查询收益。

**前置依赖**

- 领域实体类型、别名字典和关系类型定义。
- 标注样本或可人工复核的图谱评测集。
- 对模型调用成本、隐私边界和异步构图时延的约束。

**验收标准**

- 图谱中同一业务实体的别名可以归并，并保留可追溯的来源。
- 查询结果可展示明确关系类型和来源切块。
- 基准集上的实体和关系质量指标达到已确认的阈值，并证明图谱补召回优于纯向量检索的目标场景。

### P1：视觉模型和 OCR 跨模态检索

**现状**

- PNG/JPEG 可导入；文件名、图片尺寸和可选同名说明文件会转为可检索文本。
- 图片仍沿用文本向量、权限校验和租户隔离链路。

**未完成内容**

- 图片视觉 embedding 和图文共享向量空间检索。
- 图片 OCR 与结构化版面识别。
- PDF 页面渲染、页面级图片索引和图文混合引用。
- 图片内容、截图、表格和图表的跨模态问答及召回评测。

**前置依赖**

- 已选定的视觉模型或多模态模型供应商。
- OCR 服务、PDF 渲染工具链和文件大小/页数限制。
- 图像数据的隐私分级、保留策略和模型调用合规要求。

**验收标准**

- 用户可通过自然语言检索到仅存在于图片或 PDF 页面中的关键信息。
- 返回结果含图片或页面级引用，并继续遵守原文档权限和租户边界。
- 当视觉/OCR 服务不可用时，系统可降级并明确提示，不影响文本 RAG 链路。

### P1：受控诊断处置的完整回滚能力

**现状**

- 诊断页面支持只读健康指标和建议。
- 已支持审批令牌确认后的失败导入回放，并记录请求、回放和完成审计。

**未完成内容**

- 更多可审计诊断动作，例如指定知识库重建、异常索引清理和配置回滚。
- 对每种处置动作定义风险等级、执行前检查、幂等性和补偿机制。
- 处置任务的异步执行、进度查询、失败恢复和可操作回滚。
- 与组织级审批流连接，避免依赖共享静态审批令牌。

**验收标准**

- 每个处置动作均有明确的输入范围、权限要求、审批条件和审计记录。
- 异步处置可查询状态，失败时能够安全重试或回滚。
- 任何自动化动作均不得绕过租户、文档权限和审批限制。

### P2：反馈驱动的持续优化

**现状**

- 支持人工评分和评论，并将低评分汇总为诊断信号。
- 当前诊断仅给出可解释建议，不会自动修改模型或排序参数。

**未完成内容**

- 从反馈评论中识别检索遗漏、回答不准确、引用不足和权限问题等原因。
- 基于反馈数据优化 rerank、召回数量、切块策略、提示词或模型选择。
- 离线评测、A/B 实验、灰度发布、效果阈值和自动回滚。
- 反馈数据的噪声处理、防投毒策略和人工复核机制。

**前置依赖**

- 足够规模且已脱敏的反馈和评测样本。
- 业务确认的效果指标，例如命中率、引用完整率、满意度和成本上限。
- 模型与检索参数的发布、灰度和回滚机制。

**验收标准**

- 优化方案必须先通过离线评测，再进入可观测的灰度实验。
- 自动化优化不降低已确认的安全、权限和成本基线。
- 效果异常时可定位到具体版本并完成回滚。

## 建议推进顺序

1. 确认生产 OIDC Provider、租户 Claim 和组织级审批制度，完成阶段 3 的外部集成设计。
2. 完成审批状态模型和高风险操作工作流，再扩展更多诊断处置动作及回滚能力。
3. 选择视觉模型和 OCR 服务，优先用小规模图片/PDF 评测集验证跨模态检索收益。
4. 建立图谱实体、关系和查询效果评测集，再投入实体消歧和关系类型抽取。
5. 积累可信反馈和离线评测数据后，逐步引入反馈驱动的排序或模型优化。

## 不纳入当前迭代的原因

- 生产身份源和审批流需要组织基础设施、权限制度和密钥管理配合，不能在本地以默认实现替代。
- 视觉 embedding、OCR 和跨模态检索需要明确模型供应商、隐私要求、成本预算和评测标准。
- 自动化模型/排序优化涉及线上质量、成本和安全风险，必须在评测、灰度和回滚机制完善后实施。
