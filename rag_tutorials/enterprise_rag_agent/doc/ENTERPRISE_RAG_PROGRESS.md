# Enterprise RAG 需求完成进度

> 版本：v0.1
> 最近更新：2026-08-14

## 维护规则

- 每次新增、修改或完成需求后，必须同步更新本文档。
- 阶段状态只使用：`未开始`、`进行中`、`基本完成`、`完成`、`阻塞`。
- 完成度是产品和实现综合判断，不等同于代码行数或接口数量。
- 如果某项能力已有代码但缺少验收、文档或前端入口，只能标记为 `进行中` 或 `基本完成`。

## 总体判断

阶段 0 的需求定义已经基本完成，可以作为后续阶段的输入继续推进。

尚不能标记为完全完成的原因：

- 部分边界已经成文，但还需要在每次实现变更后持续回填进度。
- 风险分级、权限组、知识库范围已经定义，但仍需要在后续阶段持续验证是否被前后端完整承接。
- 阶段 0 的“前端只读展示需求”已有文档，但是否完整落地需要结合当前前端实现继续验收。

## 最近完成

### 2026-08-14

- 新增文档内容哈希 `content_hash`，用于识别已导入文件。
- 导入同路径未变化文件时跳过，避免重复切分和写入。
- 不同路径或不同知识库内发现内容相同的文件时跳过，并返回 `duplicate_paths`。
- 目录导入时清理本目录下已经不存在的旧文档索引和 chunks，单文件导入不触发目录同步清理。
- 接入配置化模型 embedding，把 chunk 向量写入 SQLite；测试场景仍可显式使用本地 hashing embedding。
- 检索排序加入向量余弦相似度。
- 阶段 PRD 文档移动到 `doc/iterations/phase-*` 目录。

## 当前重点

1. 在前端导入页展示 `documents_indexed`、`documents_skipped`、`documents_removed`、`duplicate_paths`。
2. 在文档列表页展示 `content_hash`、知识库、权限组、路径和更新时间。
3. 补齐导入异常、重复文件、目录清理的用户可见提示。
4. 为阶段 1 增加一组稳定的问答验收样例。

## 风险和待确认

- 模型 embedding 依赖 `ENTERPRISE_RAG_EMBEDDING_API_KEY` 或 LLM API key；无 key 的本地测试需显式配置 `ENTERPRISE_RAG_EMBEDDING_PROVIDER=local`。
- 目录同步清理只在目录导入时触发，单文件导入不会清理其他索引；该行为已由后端测试覆盖。
- 同内容跨不同知识库按全局去重处理；如业务需要分知识库保留重复内容，需要重新调整去重范围。
